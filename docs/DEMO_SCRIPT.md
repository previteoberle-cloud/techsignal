# TechSignal 演示讲解稿（约 2–3 分钟）

> 演示前准备：`pip install -e ".[ui]"`，然后 `python -m techsignal.workbench`，浏览器打开 http://localhost:8501。全程离线，不需要模型密钥。
>
> 讲解原则：只讲系统实际做了什么。研判和补证都是**确定性规则**，不要说成「AI 自主决策」。

---

**【0:00–0:20｜开场：问题】**

做硬科技研究时，公司官网、文档、开源仓库每天都在变。难点不在于「发现页面变了」，而在于判断「这条变化会不会动摇我之前的研究结论，证据够不够」。

TechSignal 把 changedetection.io 抓到的网页变化，转成带证据编号、可以复核的研判。

**【0:20–0:45｜原始研究判断】**

*（侧栏选择「Tenstorrent Blackhole：跨批次跟踪」，打开「研究判断」页）*

这是一个真实案例。2025 年 7 月，Tenstorrent 官方仓库 README 中，新芯片 Blackhole 只有 8B 模型的初步数据。由此得出的历史判断是：Blackhole 的大模型推理软件仍处早期，还没有 70B 级模型的官方记录。

这里的每条依据都是官方原文的逐字引用，附有提交链接。

**【0:45–1:10｜新证据变化 → 判断受影响】**

*（打开「变化时间线」，指向批次 1）*

真实运行的 changedetection.io 抓到了下一个版本：官方表格新增了一行「Llama 3.1 70B 跑在 QuietBox Blackhole 上」。

注意这里分开列了两个时间：**发布时间**是 2025 年 7 月的提交时间，**抓取时间**是系统实际读取页面的时间。

规则判定这条 A 级官方证据**削弱**了假设 BH1。但系统只建议「研究负责人复核」，**不会自己改结论**。

**【1:10–1:50｜自动补证 → 保留不确定性】**

*（切到批次 2，打开「补证过程」，打开「展开完整补证轨迹」）*

一个月后，README 改版，这一行消失了。它是被撤回了，还是只是文档重新排版？

规则看到信号只出现在删除内容里，就**不翻转**之前的判断，而是触发补证。补证由确定性策略决定查哪些地方，最多查 3 次，并且只访问白名单内的官方来源：
- 第一，在 changedetection.io 保存的新版页面里搜索；
- 第二，读取这次修改的官方提交说明；
- 第三，沿着被删除那一行里的官方链接，查同一版本的模型文档。

每一步的地址、状态和查到的原文都在这里。在云开发环境里，提交说明那一步被网络策略拒绝，系统如实记录为失败。

结果是：查到了新的官方内容，但文档只写了「QuietBox」，没有写明 Blackhole，无法区分是重排还是撤回。所以系统**保持「待核实」**，不编造结论。

**【1:50–2:20｜查看证据轨迹】**

*（点击任意证据编号，跳到「证据详情」）*

每条证据都能点开：来源、等级、发布时间、抓取时间、原始链接、原文，以及它被用在哪个判断上。

*（打开「管理层速览」，点击「下载中文速览」）*

管理层看到的是先结论后细节的中文速览，可以直接下载。

**【2:20–2:40｜可复现 + 坦诚的边界】**

*（侧栏切到「离线回放」，点击「运行离线回放」）*

用保存的原始数据重新跑一遍完整的研判流水线，结果与当时的实测一致。

最后说明边界：
- 目前没有接入任何真实大模型，所有判断都来自规则；
- 不是持续监控；
- 只有这一个真实案例；
- 研究判断需要手写配置。

这些都写在 README 里。
