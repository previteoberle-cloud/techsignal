# TechSignal R4 验收报告：全中文研究工作台

- 日期：2026-11-04
- 分支：`claude/affectionate-goldberg-u18nzv`，PR #1

## 一句话结论

TechSignal 新增了一个**全中文、可交互的浏览器研究工作台**（Streamlit）。

- 默认展示真实的 Tenstorrent 历史案例，不需要网络、Docker 或模型密钥就能启动。
- 「离线回放」和「在线连接」都调用已有的研判流水线，结果写入临时目录。
- 页面始终说明当前是离线展示还是在线连接。
- 已在真实的 Chromium 浏览器中逐页检查并截图。

**界面中所有判断都来自确定性规则，没有任何「AI 自主推理」。**

## 一、技术选择

选用 **Streamlit**：

- 纯 Python，单进程，没有前端构建步骤；
- 能直接 import 现有的 pydantic 模型和 CLI 流水线，不需要重写业务逻辑；
- 官方的 `streamlit.testing.v1.AppTest` 可以在 CI 中真实运行脚本、驱动控件，无需浏览器；
- 是可选依赖：`pip install -e ".[ui]"`。核心流水线仍然只依赖 pydantic。

代码结构：

| 文件 | 作用 |
|---|---|
| `techsignal/workbench/viewmodel.py` | 数据层：读取已保存的运行结果，用现有模型校验，推导总览、时间线、补证视图和证据视图。不依赖 Streamlit，便于测试 |
| `techsignal/workbench/replay.py` | 离线回放与在线连接：在进程内调用 `techsignal.cli.main`，结果写入临时目录 |
| `techsignal/workbench/app.py` | Streamlit 界面，共六个页面 |
| `techsignal/labels.py` | 中文标签表，简报和工作台共用，界面上不出现内部取值 |

启动方式：

```bash
cd techsignal && pip install -e ".[ui]" && python -m techsignal.workbench
```

然后打开 http://localhost:8501。

## 二、界面与交互

| 页面 | 内容 |
|---|---|
| 总览 | 研究对象、本批次变化数、当前判断、待核实事项；结论放在最前面；每条判断附带可点击的证据编号；多批次案例显示各批次概况 |
| 管理层速览 | 先给结论，再给建议动作、仍需核实的问题和补证结论；可下载中文速览 Markdown；技术细节（含判断规则）折叠在「技术详情」中 |
| 研究判断 | 原始结论、截至日期和负责人；关键假设及其在本批次的状态；结论依据的公开来源（逐字引文和原始链接）；证据等级说明 |
| 变化时间线 | 每个批次分别显示**发布时间**（git 提交时间）和**系统抓取时间**（changedetection.io 实际读取页面的时间）；版本链接；关键变化行高亮；影响方向；与上一批次相比的变化说明 |
| 补证过程 | 为什么补证、结果、结束原因、规则提示；每一步查询的工具、目的和成败；「展开完整补证轨迹」开关显示请求地址、尝试次数和匹配到的原文 |
| 证据详情 | 来源、来源类型、证据等级、获取方式、发布时间、抓取时间、「打开原始公开来源」按钮、新增或删除的原文、用于哪些判断（包括补证结论） |

交互：

1. 选择研究案例。
2. 选择数据来源：历史实测演示 / 离线回放 / 在线连接。
3. 选择查看批次（多批次案例）。
4. 点击任意证据编号，跳转到该证据的详情。
5. 展开或收起完整补证轨迹。
6. 下载当前批次的中文速览（Markdown）。
7. 运行离线回放（可选择同时执行补证）。
8. 填写自己的 changedetection.io 地址和 API key，拉取变化并研判。

## 三、本轮发现并修复的两个问题（非界面问题）

1. **多批次案例的证据来源地址错误（自 R2 起存在）。**
   - 现象：在线测试脚本先观测完全部三个版本，再逐批调用 API；而 API 返回的是**调用那一刻**监测项的 URL。结果批次 1 的证据被标成了版本 3（`62f3cd0`）的地址。
   - 修复：改为观测一个版本、立即调用一次 API。
   - 跨批次案例已真实重新在线运行，现在批次 1 的来源是 `168a956`，批次 2 是 `62f3cd0`。新增回归测试 `test_each_batch_points_at_its_own_version`。
   - 工作台还会优先按快照时间戳匹配发布时间，作为第二道保险。
2. **中文速览中的「补证记录」夹带内部英文取值**（如 `cross_batch_unresolved`、`deterministic`、`plan_completed`、`cdio_snapshot_search`）。
   - 修复：改为使用共用的中文标签表。案例已重新运行。

## 四、离线、无模型与安全

- **离线可用：** 没有网络、Docker 或模型密钥时，「历史实测演示」可以正常打开，内容全部来自 `techsignal/cases/` 中已提交的真实运行结果，页面明确提示「当前为离线展示……没有连接任何在线服务」。
- **离线回放：** 只读取已保存的原始响应和运行记录，每个批次都核对 sha256，结果写入 `tempfile.mkdtemp()` 创建的临时目录；测试会校验 `techsignal/cases/` 的文件哈希在回放前后不变。默认不执行补证；勾选后才会访问白名单内的 GitHub 地址。
- **在线连接：** 连接失败时只显示错误信息，页面保持离线状态，不展示任何伪造的实时数据。API key 只在本次会话的内存和本次调用的环境变量中使用，不写入任何文件。
- 不依赖 Claude Code 环境；没有加入公司内部材料或密钥；没有修改 changedetection.io 上游代码；外部访问继续遵守 R3 的白名单和 URL 检查。
- 界面侧栏和来源标签始终注明「模型：未使用……不是 AI 自主推理」。

## 六、回答 Owner 的问题

**A. 哪些界面数据来自真实历史案例？**

默认的「历史实测演示」中，全部数据来自真实运行：

- `cases/tenstorrent_blackhole/output/`（单批次）；
- `cases/tenstorrent_blackhole/output_cross_batch/`（两个批次）。

这些都是真实 changedetection.io 抓取 Tenstorrent 官方仓库 README 三个提交版本的结果，以及 R3 补证工具对 GitHub 的真实查询结果。研究判断的结论依据是逐字引用的官方原文。界面上没有任何编造的企业或数字。

**B. 哪些交互实际调用了已有 Python 代码？**

- 「运行离线回放」：通过 `replay.replay_case` → `techsignal.cli.main`，执行完整的研判流水线，包括适配器、去重、规则、跨批次历史、简报和引用校验。勾选补证时，还会运行 R3 的补证引擎。
- 「拉取变化并研判」：通过 `replay.fetch_live` → `ChangeDetectionClient` 加上 CLI 在线模式。
- 所有页面的数据：由 `viewmodel` 使用现有的 pydantic 模型（`Brief`、`Evidence`、`Thesis`）读取和校验。

**C. 哪些只是只读展示？**

「历史实测演示」模式下的六个页面都是只读展示：读取已保存的结果，不重新计算。切换批次、点击证据、展开轨迹、下载速览，都只是读取和导出，不写任何文件。

**D. 无网络、无模型的情况下能否启动？**

能。「历史实测演示」和不勾选补证的「离线回放」完全离线，不需要模型密钥或 Docker。这一点有 CI 的 `ui` job（无网络依赖）和本会话测试作为证据。

**E. 实际浏览器验收和 CI 是否通过？**

- 浏览器验收：本会话已用真实 Chromium 完成，具体见第五节，截图已入库。
- CI：见下方补充记录和 PR #1 的检查结果。

**F. 普通研究人员现在能完成什么，还不能完成什么？**

现在能：

- 不写代码，在浏览器中打开已保存的真实案例；
- 看懂系统发现了什么变化、原判断为什么被削弱或转为待核实、补证查了什么以及成没成功、哪些问题仍待核实；
- 点开每条证据查看原文和官方链接，分清发布时间和抓取时间；
- 下载中文速览；
- 用已保存的数据重新运行一次研判，确认结果可复现。

还不能：

- **新建研究判断或调整判断规则**：仍需手写 JSON 和正则；
- **持续监控**：没有后台调度和通知，需要另外部署 changedetection.io；
- **使用任何模型能力**：没有授权的模型服务，表格以外的写法无法定向；
- **多用户和权限管理**；
- 在当前云容器内访问公司官网、新闻稿等来源（网络策略限制）。
